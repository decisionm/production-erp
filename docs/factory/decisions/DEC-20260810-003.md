A finished product's Tally identity is editable configuration, and each packaging variant may carry its OWN Tally identity. When the factory packs one physical product more than one way (the raising case: B.200 Ml Round Pet Bottle Amber 18gms — tray/pouch, 490/box vs 520/box, with the Tally books carrying a different Tally item per packing), each packaging row (tray/pouch/box) holds the Tally item its production posts as: the same value on both rows when Tally does not distinguish the packings, a distinct value on each when it does. A packaging with no identity of its own falls back to the product's identity, shown with a visible 'using product identity' note and an edit option in place — an unknown identity is left editable, never guessed. The packaging the supervisor selects for a batch decides the Tally item name everywhere: batch preview, completion, ERP stock booking, the consolidated shift voucher (aggregated per RESOLVED identity, so two packings of one product land as their two Tally lines), carton trace, and the View modal. Both edit affordances live in Production Configuration, gated on production.manage with provenance recorded, same pattern as the Packing Materials tab. Vouchers already posted are history and stay as posted. The 200ML RA 490/box tray variant (98/tray x 5, per the 07-Aug paper) is created as a proper packaging variant with its Tally identity initially UNSET for the owner to set in the edit UI; the 490-vs-'520 Nos' naming discrepancy is a recorded owner question, not resolved here.
