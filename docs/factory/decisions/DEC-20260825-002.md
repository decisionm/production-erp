Automatic sync to Tally stays exactly the three shift-end release waves already in force: DEC-20260807-011's gate is unchanged and nothing here loosens it. In addition, the ERP's Tally Sync page carries a "Sync Now" button, which is a REQUEST that the outbound vouchers currently queued in the ERP post on the agent's next poll - the queue-wide form of the per-voucher accountant override DEC-20260807-011 already grants, not a new automatic rule. Boundaries: Sync Now never pulls masters or stock FROM Tally, and it never posts, delivers or acknowledges a voucher from the browser - only the local agent posts to Tally, and only vouchers already queued are affected. Only an Owner/Accounts permission may press it. If the agent is offline the request simply waits until the agent next polls; nothing is lost, and the ERP never claims a voucher posted that has not. Duplicate or concurrent clicks must not create a duplicate queue entry or a duplicate Tally voucher - a repeat click is a no-op on the queue, while every press is recorded. The factory tray's own "Sync Vouchers Now" stays exactly as it is.
