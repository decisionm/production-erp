When a purchase order is CANCELLED its quantity does NOT return to the purchase requisition's balance, provided the order had been sent. A requisition is asked for once and answered once: an order that reached the vendor has spent the requisition's allowance, and wanting that material again means raising a NEW requisition, which is a fresh approval by whoever approves them. The requisition, not the order, is the unit of authorisation. This answer needed a third one to be coherent, and it is part of the same decision: a cancelled order counts ONLY IF IT WAS EVER SENT. Because a draft reserves nothing, cancelling an unsent draft must release nothing — it was holding nothing — and without that qualification cancelling an abandoned draft would permanently consume a requisition the draft never held, so a typo could eat a requisition. The ERP records purchase_orders.sent_at to tell the two apart; rows already Sent, PartiallyReceived or Closed when the column was added are backfilled, and rows already Cancelled are left null and so read as never-sent, because the fact was not recorded and inventing one would decide a live requisition's balance on a guess.
