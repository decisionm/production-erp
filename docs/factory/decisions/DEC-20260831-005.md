Material remaining in Production/WIP stays available for the next production day, INCLUDING existing material that no Store Issue put there. A batch consumes from Production/WIP whenever that location holds a non-zero balance of the material, whatever put it there. This replaces the previous two-condition rule which also required that a Store Issue had put the material there, and which therefore sent tomorrow's batch to the Store while the WIP kilograms sat untouched -- the position seven of the nine live materials standing in production were in. What is new and worth knowing: those materials now draw down WIP to zero and then continue from the Store, and both movements carry purpose consumption differing only in warehouse_id, so the point at which the floor ran out is not marked in the ledger.
