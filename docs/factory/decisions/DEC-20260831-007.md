A batch consumes from Production/WIP whenever that location holds a non-zero balance of the material, INCLUDING existing material that no Store Issue put there. FactoryWarehouseResolver::consumptionSource previously also required that a Store Issue had put the material there, so for the seven of nine live materials standing in production with no issue behind them the batch drew from the Store while the WIP kilograms sat untouched. Removing that condition does not open the over-consumption hole it guarded, because the surviving condition tests for a NON-ZERO balance rather than a positive one: an over-draw leaves Production/WIP negative, so it stays the source and the completion's shortfall record fires. What IS new: those materials now draw WIP to zero and then continue from the Store, and both movements carry purpose consumption differing only in warehouse_id, so the point at which the floor ran out is not marked in the ledger.
