ACCOUNTS APPROVAL REFUSES A BATCH WHOSE STOCK JOURNAL CANNOT POST, ONCE THE TALLY MASTERS ARE PROVEN ON LIVE. Accounts approval is the transition that queues the batch's Tally Stock Journal, so it is the posting gate: when the voucher the batch would build is not postable - an item with no Tally identity, a godown Tally does not know, a packing store nobody has named - the approval is REFUSED and the refusal names the cause, using the same payload builder the real post uses so nothing can drift. This records the owner's 31-Jul-2026 instruction, until now carried only in a code comment: 'If the Tally preview is invalid, posting must remain unavailable.' ROLLOUT ORDER, part of the rule and the same as DEC-20260902-017: the gate is NOT switched on immediately. First the Tally masters are loaded and the voucher preview is checked against real batches on live, with no value invented; then the switch is thrown (production.approvals.require_postable_voucher). Until then the gate stays watch-only exactly as shipped and approval behaves as it does today. A LOCAL- fixture batch stays exempt whichever way the switch is set, because no voucher is ever built for it. The four-eyes rules of the chain are unchanged (FC-05, DEC-20260902-010).
