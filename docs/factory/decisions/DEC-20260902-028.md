THE ERP NEVER MOVES A FINISHED-GOODS HOLD ON ITS OWN: THE FIRST HOLD PLACED KEEPS THE STOCK, AND ONLY A PERSON RE-POINTS IT. When the free quantity of a finished good cannot cover two sales-order lines, the hold placed first survives. A promised date, an order date or any other attribute never causes the ERP to release or re-point a hold automatically. A hold moves only when a Store user re-points it from one line to another, in one step that releases and re-takes it, with a reason recorded and the action audited - exactly the shipped behaviour, which this decision confirms as the factory's rule. Which customer waits is a commercial call made by a person, never a rule the ERP applies silently. Resolves Q62(a). Expressly NOT decided here: whether a re-point needs anybody's approval (Q62(b)), any customer priority (Q62(c)), the production request queue order (Q62(d)), when a request counts as answered (Q62(e)) and the parallel-lines planning figure (Q62(f)).
